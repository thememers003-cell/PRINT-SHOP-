# Print Bro Multi-Shop Printing Platform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a production-grade, multi-tenant web-first Xerox shop management and online printing SaaS ("Print Bro") with Super Admin dashboard, Shop Owner POS dashboard, Customer upload/preview/pricing/checkout portal, real-time live order tracking, and a headless Windows Print Agent.

**Architecture:** Next.js (App Router) full-stack monorepo with Prisma ORM (PostgreSQL/SQLite dual-mode), Server-Sent Events (SSE) for live order tracking, cloud-side dynamic PDF imposition/slicing via `pdf-lib`, and a standalone Node.js Windows Local Print Agent executing spooler jobs via `pdf-to-printer` and Windows PowerShell.

**Tech Stack:** Next.js 14/15, React 18/19, TypeScript, Tailwind CSS, Lucide React, Prisma ORM, `pdf-lib`, `pdfjs-dist`, Server-Sent Events, Vitest, Node.js, `pdf-to-printer`.

**Spec:** docs/superpowers/specs/2026-11-04-print-bro-design.md

---

## Global Constraints
- Target workstation OS for local printing: Windows 10/11 using Windows Print Spooler.
- Multi-tenancy: Dedicated shop URL routing via `/shop/[slug]` with strict shop data isolation.
- Commercial Model: Centralized platform Merchant of Record; customer payments captured centrally with platform commission split and shop settlements.
- Security: Server-side authoritative price validation (never trust client amounts).
- Print Reliability: Idempotent job dispatch with unique Job ID (`PB-YYYY-XXXXXX`) and no dependency on keeping browser tabs open.

## Review Focus
1. **Malformed or encrypted PDF upload**: Returns a structured error rather than throwing an unhandled exception or 500 error.
2. **Duplex page odd-count calculation**: Single 3-page document on duplex correctly computes 2 physical sheets (3 printed sides) and charges accurately.
3. **Double-submit on payment confirmation**: Idempotent order checkout prevents duplicate order/payment records.
4. **Agent network disconnect & reconnect**: Agent catches connection drops, backs off, reconnects, and does not reprint already completed jobs.
5. **Inactive or suspended shop URL**: Accessing `/shop/[slug]` for an inactive shop displays a clear suspended notice and rejects document uploads.
